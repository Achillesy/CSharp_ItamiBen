# ItamiBen — 一袋米要我洗嘞

> **Too dumb to make excuses for you.**（笨到没法替你找借口。）

一个会较真的番茄钟。先划定自己允许做的事，再承诺一段专注，整段时间里它盯着前台窗口。
一走神，那些分钟就是不算——休息区往后挪，你眼睁睁看着它越推越远。

不弹窗、不唠叨、也不恭喜你。就是一台笨到没法跟你讲条件的钟。

**状态：早期，但能跑。** macOS 上端到端验过；**Windows 那一半到现在一次都没跑过。**

[English](./README.md)

## 跟别的番茄钟不一样在哪

多数番茄钟是「靠自觉的秒表」：你按下开始，25 分钟后它恭喜你，完全不管这期间你干了什么。
ItamiBen 会判。**只有当你真正看着的那扇窗口命中你事先写好的规则，那一秒才算数**——
事先写，不是事中改。

它**不依赖 ActivityWatch**：自己每秒读十次前台窗口，每秒往自己的数据库落一行。
（前作 ItamiTimer 建在 ActivityWatch 上，事实证明那个地基不适合干这件事，本项目是重做。）

ItamiBen 自己也**没有任何特例**：盯着它自己的钟面就是跑偏，跟盯着别的什么一样。

## 一轮是怎么走的

1. 选一个目标（**单选**，而且默认已经选中一个）。
2. 拖滑块——10 到 50 分钟，步长 5。它**没有数字也没有标签**，意义就在于靠猜。
3. 按 **Start**。从这一刻起，钟每秒读一次前台窗口。
4. 专注目标达成后是一段休息：`⌈专注 ÷ 5⌉` 分钟。

这一切都发生在一个**两小时的环**里。硬就硬在这儿：环是**墙上时间**，它不会伸长。
凡是没在专注的秒——跑偏、离开键盘、锁屏、甚至盯着 ItamiBen 自己——吃的是同一份预算：

    预算 = (120 − 休息) × 60 − 目标
    余量 = 预算 − (走过的秒 − 专注的秒)

余量见底，这一轮就结束。**没有任何办法把它赚回来。**

### 环上画的是什么

每一分钟是环上的一块桶板：

| 这一分钟发生了什么 | 长什么样 |
|---|---|
| 大部分时间在专注 | 高高的绿色桶板 |
| 部分专注 | 矮一些，颜色走绿 → 黄 → 红 |
| 跑偏 | 一块矮的红桶板 |
| 人不在（键鼠空闲满 3 分钟） | **空心虚线框**——时间确实过去了，但不怪你 |
| 什么都没采到 | 什么都不画 |

颜色和高度**故意编码同一个量**：一个给正常视觉，一个给所有人——红绿是最常见的色盲混淆对。

指针前方那块描边的区域是休息区。**那就是全部的惩罚**：每浪费一分钟它就往后挪一分钟，
你眼睁睁看着它跑远。

### 跑偏的时候

跑偏期间钟面每秒半反色翻一次，滴答声跟着起来。**除此之外什么都不发生。**
右上角的喇叭图标可以把跑偏的滴答静音。

## 窗口

无边框、置顶，所以它像挂在桌面上的钟，不像一个程序。**拖动要拖钟面**（可拖区域是圆的，
不是方的）。

- **在钟面上滚滚轮**拨黄色的闹钟针，一直滚会加速。
- **右键钟面**：置顶 · 强制滴答 · 闹钟到点跑命令 · 关闭窗口。
- **点那个小红圈**，瞄一眼 12 小时内的下一条 `alarms.cron`，只留 3 秒，纯读不改任何东西。
- 钟面下面那**七个骨牌**是星期几，倒下的是已经过去的那几天。
- **最底下那一栏**显示钟此刻读到的前台程序和窗口标题——**你的规则就是拿它来匹配的**。
- 齿轮开设置；图钉切置顶；第三个图标切明暗主题。

### 把窗口缩小，和让它透出后面的东西

在规则文件旁边放一个 `layout.json`：

```json
{ "layout": "compact", "opacity": 75 }
```

`layout` 取 `standard`（宽 380）或 `compact`（宽 292）。`opacity` 取 0~100，
**只作用在钟面和卡片底色上**——按钮和文字保持实心，把它们一起调淡只会让人没法读。

**只在启动时读一次。**

## 你的文件

都在 `~/Library/Application Support/ItamiBen/`（macOS）或 `%APPDATA%\ItamiBen\`（Windows）。

| 文件 | 谁写 |
|---|---|
| `rules.json` | **你写**，程序只读。默认的那份随程序发在 app 里面。 |
| `alarms.cron` | **你写**，可选，每分钟重读一次。 |
| `layout.json` | **你写**，可选，只在启动时读。 |
| `during.json` | 程序写。每个目标的累计小时——就是目标右边那个数。 |
| `samples.db` | 程序写。观测、轮次、事件**和设置**都在这里面。 |
| `itamiben.log` | 程序写。只装**够不着数据库**的话，正常情况下是空的。 |

你写的那三份里，**注释和尾逗号都允许**。

这条分界就是重点：**你写的那三份，程序只读；程序写的那些，你只看。**
音色、窗口位置、闹钟时刻这些原来在 `settings.json` 里，现在是 `samples.db` 的行——
反正你从来不手改它，**少一个文件就少一处要同步的东西**。
已有的 `settings.json` 会被搬进去一次，然后改名成 `settings.json.migrated`。

### rules.json

```json
{
  "Groups": {
    "编程": {
      "Rules": [
        { "App": "^(Code|claude)(\\.exe)?$" },
        { "Title": "GitHub" }
      ]
    },
    "不做了的目标": { "Disabled": true, "Rules": [] }
  }
}
```

`App` 和 `Title` 都是正则。一条规则里两个都写就**都要中**；一个组里**任意一条**中就算中。
不再用的目标**写 `Disabled` 而不是删掉**——删了以后想找回来还得重写一遍。

⚠️ **正则区分大小写，而且两个平台报的名字不一样。** macOS 报 `Claude` / `Code`，
Windows 报 `claude.exe` / `Code.exe`。从 Windows 搬到 macOS 的规则文件**一条都不会命中，
而且不报错**——症状是整轮全红，而那看起来跟「你今天确实没干活」一模一样。
两种写全：`^(Claude|claude\.exe)$`。

### 累计小时数从哪来

目标右边那个数是它的终身累计，存在 `during.json`，**在一轮以受控方式结束时写一次**
（达成、Give up、关窗口、SIGTERM）。`kill -9` 只丢这一轮的累计——**轮次本身**下次启动
会从 `samples.db` 重建出来，连指针位置都一样。

## 周期提醒（alarms.cron）

一份**标准 crontab**——Vixie 语义，没有自己的方言——第 6 列是**提醒文字，永远不会被执行**：

```
# ItamiBen alarms.
# 第 6 列是提醒文字，不是命令，永远不会被执行。
#
# 分   时    日  月  周     提醒文字
  30   9     *   *   1-5    起来动一动
  0    7     *   *   *      注释掉的这条不响
```

「日 / 周」那条 OR 规则是 Vixie 的，而且实现了：两栏都被限制时，**任意一边中就算中**。

到点时**同时**给你两样，这是故意的：

- 骨牌上那条提示条，保证**屏幕上一分钟内一定看得见**；
- **系统通知**，**一条事件一个、永远不合并**——提示条有硬高度上限、多出来的只剩一个 `+N`，
  **通知中心那一份才是不丢内容的**，而且关掉程序还翻得回来。

设置里的 Alarms 开关**只管响不响铃**，提醒本身永远会出。

## 闹钟，以及它到点的时候发生了什么

那根黄针就是一个普通的墙上闹钟，**跟专注判定毫无关系**。在钟面上滚滚轮设定；
它是**一次性**的，响完自己清掉；重启之后还在。

到点时：

1. 选定的系统音**响 4 遍**（专注相关的那三声只响 2 遍——它们各自都在屏幕上留下了一个
   看得回来的状态；闹钟响完什么都不留）。
2. **只有**右键菜单里的「Run command at alarm」开着时，才会跑 `executeCommand` 里
   当前系统的**第 0 条**。

```json
"executeCommand": {
  "macos":   ["pmset displaysleepnow", "osascript -e 'tell application \"System Events\" to sleep'"],
  "windows": ["rundll32.exe user32.dll,LockWorkStation", "shutdown /s /t 0"]
}
```

⚠️ **永远只跑第 0 条。** 这是个常用命令的**收藏夹，不是配置格式**：想换就重排顺序，
**刻意不做界面去选**。

⚠️ **那个开关每次启动都是关的。** 持久化它是事故：重启之后被上一个会话的关机命令拍死，
而你根本不知道它还开着。

设置窗口会把**到点真正会跑的那条命令原文**显示出来。这个值多半是关机命令，
**按下开关之前你有权知道按的是什么。**

## 环境要求

- 运行要 .NET 10 Runtime，编译要 SDK
- Windows 或 macOS

⚠️ **macOS 需要辅助功能授权才能读窗口标题。** 没有授权程序照样跑，但**只能读到程序名**，
所有按标题写的规则**静默地永不命中**。程序会在状态栏里告诉你，并给一个按钮直接打开那一页。
**不需要重启进程，下一拍就生效。Windows 不需要任何授权。**

## 编译与运行

```bash
dotnet build ItamiBen.slnx
dotnet test  ItamiBen.slnx
./run-macos.sh              # 编译 → 打成 .app → 签名 → 启动
./run-macos.sh --run-only   # 只启动，不编译不重签
```

⚠️ **macOS 上别用 `dotnet run`，也别直接跑 `bin/` 里的裸二进制。**
辅助功能授权按「应用」记账，裸二进制拿不到——症状是**只读得到应用名、读不到窗口标题**，
一半的规则从此静默失效。必须走 `run-macos.sh` 打出来的 `.app`。

## 发布

```bash
./pack-macos.sh             # → dist/ItamiBen-<版本>-macOS-<架构>.dmg
pwsh pack-windows.ps1       # → dist\ItamiBen-<版本>-win-x64.exe（需要 Inno Setup 6）
```

两边都是**依赖框架**的，目标机器上要先装好 .NET 10 Runtime。Windows 的安装包会自己检测
并提出替用户下载；macOS 的 `.dmg` 在 Read Me 里说明。版本号**只有一个出处**：
`Directory.Build.props` 的 `<Version>`。

⚠️ **Windows 那一半从没在真机上跑过**，`pack-windows.ps1` 和 `installer/ItamiBen.iss`
都是纸面代码。

## 调试出口

**不是产品功能**——跑完就退，正常启动路径根本不经过它们：

```bash
ItamiBen --query samples  [起] [止]         # 一秒一行的原始观测
ItamiBen --query events   [起] [止]         # 闹钟 / 提醒 / 命令 / 出错
ItamiBen --query rounds   [起] [止]         # 开过哪些轮、怎么结束的
ItamiBen --query minutes  [起] [止]         # 每一轮逐分钟的构成，红的还给出是哪扇窗口
ItamiBen --dial-specimens <输出目录>        # 钟面在几个关键状态下的离屏样张
ItamiBen --export-icon    <输出.ico>        # Windows 图标
ItamiBen --export-iconset <输出.iconset>    # macOS，再 iconutil -c icns
```

**这个程序没有运行日志。** `samples.db` 就是记录，出了问题直接查它。
`itamiben.log` 只剩一个用处：**装不下在数据库里的那些话**——库自己打不开、被单实例挡回去、
启动早期就崩了。正常跑一天它一个字节都不长；**里面有东西 = 出事了**。

`--query minutes` 是回答「这一分钟为什么没算」的那个：它从库里把那一轮重放一遍，
并指出红是哪扇窗口造成的。⚠️ 它用的是**当前**的 `rules.json`，所以你要是改过规则，
回头看老轮次会跟当时的判定对不上。

`--dial-specimens` 把钟面在几个关键状态下渲成 PNG 供人眼检查——钟面活在界面层，
单元测试够不到，而半径、角度、图层顺序这类问题真的只能靠看图抓。

图标跟别的东西一样是**代码画的**，仓库里一张位图都没有。

## 项目结构

```
src/ItamiBen.Core/    判定与计时的纯逻辑，零 UI 引用，可单测
src/ItamiBen.App/     Avalonia 界面；平台调用只允许出现在这一层

```

## 名字

「一袋米要我洗嘞」是**痛みを感じろ**的空耳，而「大笨钟」是 Big Ben 在中文里的日常叫法
（字面就是「又大又笨的钟」）。Big Ben 准时、响亮、没法跟它讲条件——这就是整个产品主张，
所以名字本身就是主张。
